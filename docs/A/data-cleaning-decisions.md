# 数据处理说明（大白话版）

> 负责人：A（钟诗宇）。脚本 `src/build_panel.py` 一键重跑。报告 §3 直接从这里取材。

## 我们做了哪几件事

### 1. 挑出 CEO

薪酬表里 6,039 行记录，只有 1 行是 CFO，其他全是 CEO。把那 1 行 CFO 删了，剩 6,038 行。

### 2. 把两张表拼起来

薪酬表（谁、哪年、拿了多少钱）和财务表（哪家公司、哪年、业绩怎么样）有共同的编号（GVKEY = 公司身份证号）+ 年份。按「公司+年份」对上号拼成一张大表。

好消息：拼完之后天然就是「一行 = 某家公司某一年 + 它的 CEO」，正好是作业要求的格式，不用额外处理。

### 3. 找出「明年业绩」—— 这是整个项目的关键一步

我们要预测的是「这家公司**明年**业绩会不会大跌」，所以每行都要找到同一家公司**下一年**的 ROA（ROA = 公司用全部资产赚钱的效率，越高越好）。

规则很简单：只认「紧挨着的下一年」。如果某公司 2012 年的数据缺失，那 2011 年这行就找不到「明年」，只能放弃（不然拿 2013 年冒充 2012 年就是作弊）。

结果：6,038 行里有 **3,894 行**成功配上了下一年（2011 年的 1,968 行 + 2012 年的 1,926 行）。2013 年是数据里最后一年，没有「明年」，所以不参与训练。

### 4. 缺失值怎么办（作业硬性要求二选一：删掉 或 用平均值补）

先看了每个指标缺了多少（见 `analysis-output/missingness.csv`），然后按一条线处理：

| 情况 | 处理 | 例子 |
|---|---|---|
| 缺得太狠（超过 15%） | **整个指标不要了** | CEO 任职年限（100% 缺，完全没数据）；净利润变化（17.8% 缺） |
| 缺得不多（0–9%） | **用平均值补上** | 其他 14 个指标都这样处理 |

为什么这么分：缺了一半还硬用平均值补，等于编数据；缺个百分之几，用平均值补一下影响很小，而且这是作业明确允许的做法。

### 5. 造了哪些「线索」（特征）

全部用的是**当年已知**的信息，绝不偷看未来（偷看 = 作业直接挂）：

| 类别 | 具体是什么 |
|---|---|
| 薪酬 | 总薪酬（取了对数，让数字更好处理）、工资占总薪酬比例、奖金占比、股票+期权占比 |
| 公司规模 | 总资产、销售额、市值（都取对数） |
| 业绩与负债 | 当年 ROA、杠杆率（借钱做生意的程度） |
| 增长 | 销售增长、资产增长 |
| 过去表现 | 过去 1 年、3 年的股票回报 |
| CEO 个人 | 年龄 |

### 6. 定义「坏结果」（要预测的答案）

**主定义**：这家公司明年的 ROA 比今年掉得特别惨——掉分幅度排在所有公司里最差的 20%（10 家里最差的那 2 家）→ 标记为 1（值得优先审查）。按这个定义，正好 20% 的行被标记。

**一个要坦白的事**：作业建议「相对同行业调整」，但数据里**没有行业信息**（不知道每家公司属于什么行业），所以改成「相对全样本」。这点报告里会明说，作业原文也允许（"document your choices"）。

**备用定义**（防止老师问「换种定义结论还成立吗」）：① 最差 25%；② ROA 下降超过 5 个百分点。建模脚本里会自动跑这两版对比。

## 给建模同学（C）的一句提醒

平均值要用**训练那部分数据的平均值**去补测试部分，不能拿全数据的平均值（否则等于提前偷看了测试集信息，虽然影响很小但要规范）。
